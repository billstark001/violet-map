# Overlay rendering reference: phases 5–6

Measured 2026-10-17 on Apple M3 / macOS arm64, Headless Chrome 155.0.0.0 with SwiftShader enabled, viewport 800×600 CSS pixels, DPR 1. Run `pnpm build && pnpm test:overlays` to regenerate screenshots and JSON in `LOCAL_railway_deploy/overlay-acceptance/`. All cases use the same browser, camera, terrain patches and a 60-frame measurement window after resources settle.

Typical means 20 curves, 4 areas and 8 media instances sharing 2 versions. Pressure means 500 curves, 20 areas and 40 instances sharing 2 versions; the visible-feature budget suppresses 48 features. Images are a 16×8 colored-alpha fixture; the model is a small static cube. The pressure fixture measures feature bookkeeping and draw calls, not worst-case model complexity. Load requests include manifest/media and browser resource fetches during context activation; the settled frame window makes no additional content requests. CPU times measure `OverlayManager.update` plus renderer submission on the main thread; they exclude asset initialization and mesh workers. Frame intervals are paced by the browser. JS heap readings are approximate and not forced-GC retained sizes. GPU byte values are estimates of media buffers/textures and the actual RGBA mask dimensions; driver overhead, shaders and terrain storage are excluded. These results do not establish production FPS, total GPU memory use or the final phase 7 release budget.

Dense curve reference samples in perspective and orthographic projection stay within 0.51 CSS pixels of the sampled polyline. Actual 8-pixel curves measure 8 CSS pixels in both top projections. A 2-block curve measures 10 pixels at camera Y=150 and 4 pixels at Y=300, with the curve at Y=35. The sampler documents its point/depth caps and eye-plane degradation in [the format/display guide](overlays.md).

The WebGL suite checks world-XZ masks against terrain heights 0, 12 and 24, using online, LOD and offline top-map materials in both top projections. Opacity 0 leaves the base color, opacity 1 replaces it, and red/blue partial overlap follows stable feature order. Player walls match the finite extrusion, show from inside/outside, obey a solid occluder by default and overpaint it only with `occlusion: always`. `water-intersecting-walls.png` records the approximate sorted-transparency reference; intersecting walls/water are not order-independent.

PNG, JPEG, WebP and a viewBox SVG enter through the built CLI and a real API under `/violet/`. Pixel and bounds assertions cover row orientation, bottom-left anchoring, explicit aspect ratio and transparent borders. The GLB reference checks translation, positive scale, a 45-degree Y rotation and shared model resources. Models remain visible at both day factors in Overworld, Nether and End; label mode remains unlit. Unsupported GLB extensions and external dependencies fail explicitly. Publishing a new PNG version leaves the bound old version visible until a layer revision explicitly changes its pinned version.

Removing one shared-model instance retains the remaining instances without a second media download. Five load/disable cycles return every overlay media/mask byte counter to zero and renderer counts to the same baseline: 3 geometries, 6 textures and 2 programs. Unit tests additionally cover delayed canceled decode disposal, request generation checks, ETag retention, download failures and unknown media alongside a working curve. The browser suite validates the built viewer's map control, toggle, actual visible upgraded image and legacy capabilities with no overlay/media/GLB requests. The production GLB loader bundle is separate, about 44 kB uncompressed / 13 kB gzip, and is absent from the entry HTML's preload list.
